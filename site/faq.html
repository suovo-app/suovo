FAQ

Common questions

Answers about setup, access, and the limits of the MCP connection.

Is Suovo-MCP a cloud service?

No. It is an opt-in service on your computer, available only while the Suovo desktop app is running. Your configured email, marketplace, and model providers still handle their own requests.

Can MCP send or retry customer replies?

No. It can create or update a proposal in the Reply Review Queue, but it cannot approve, send, deliver, or retry a reply. Those actions stay in Suovo’s app-controlled workflow.

Does a generated draft get sent automatically?

No. generate_draft returns editable draft text and citations. Nothing is sent by that tool.

Why does my client receive conversation data?

A tool returns the local information it needs to do the requested work. That can include support conversations or queue content. Only connect a client you trust with that information.

What should I do after HTTP 401?

The client is missing the token or has an old one. Copy the current token from Suovo Settings; if you rotated it, replace the old value in the client. See the connection guide.

Why can a call fail even though the endpoint is running?

Some tools also need a connected account, a configured provider, the Suovo sidecar, or a licensed tier. generate_draft requires a licensed tier. Check the tool reference and the app’s status.

Which clients are supported?

Suovo works with Codex and Claude Code, and Settings can connect them for you. Other MCP clients should work when they support Streamable HTTP and a bearer authorization header; use the manual setup in Settings and check that client’s documentation.
